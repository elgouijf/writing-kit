# Explaining to the user

Read `kit/rules/explaining.md` before answering. It is short; the rules that matter most:

- Build every mechanism from zero: analogy, construction on a tiny example, formula, then the source's own example (E1).
- Define every difficult term where it first appears (E2).
- For a formula: the formula, each symbol on its own line, what each part means, one analogy, a minimal numeric example, how to read the value (E3).
- When the user asks for text, answer in text; a figure supports an explanation, never replaces it (E4).
- Lay out the full content when the user needs it, and keep the complete version in a course book (E5, `course-book` skill).
- Mark what is not in the source, and recompute every number (E8).

Profile P6 in `kit/rules/profiles.md` sets the voice. For prose quality, `kit/rules/register.md` and `kit/rules/banned.md` apply here too.

When the user corrects an explanation, append the lesson to `kit/lessons/INBOX.md` in the same turn (see the writing skill, step 4).
